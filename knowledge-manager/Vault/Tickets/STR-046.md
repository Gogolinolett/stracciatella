# Problem

How large should the item-entity search radius be in COLLECTING, given that drops bounce away from the mined block?

# Lösung

Decision: use player.getBoundingBox().inflate(8.0) for the item-entity AABB query in tickCollecting. Alternatives: 4 blocks, equal to reachDistance pro: matches mining reach; contra: drops can bounce 2-3 blocks from the mined block, so a 4-block AABB from the standoff position can miss drops 5-6 blocks away. 8 blocks (chosen) pro: covers the bounce radius; contra: in a real session it may match unrelated drops from another player. 16 blocks pro: always finds every drop; contra: larger scan cost and more false matches from nearby mobs dropping items. Rationale: 8 blocks covers the worst-case bounce while keeping the scan cheap, and the lastMinedPos walk ensures the bot actively moves toward its own drop rather than waiting passively.
