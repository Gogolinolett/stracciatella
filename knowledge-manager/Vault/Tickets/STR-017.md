# Problem

Should the camera spring physics parameters be runtime-configurable or hardcoded?

# Lösung

Decision: the spring physics parameters (TURN_ACCEL=0.8, TURN_FRICTION=0.8, PITCH_ACCEL=0.5, PITCH_FRICTION=0.7) are hardcoded constants in CameraController, not configurable at runtime. Alternatives: hardcoded constants (chosen) pro: simple, no config files, and the values are proven stable; contra: requires a code change to tune. Config file (camera.json) pro: tunable without recompile; contra: extra complexity and another config to manage. Passed from consumer config pro: flexible per consumer; contra: couples the camera module to the consumer config. Rationale: the values are well-tuned from extensive testing, and runtime tuning via config commands was removed to simplify the system. Per-target variation comes from the look-speed multiplier rather than from tunable constants, because multipliers are unit-less and easier to reason about than re-tuning the physics directly. See also [[STR-021]].
