# Problem

The ender pearl use press is silently rejected by the server and the travel method fails - how long must keyUse be held?

# Lösung

Decision: hold keyUse for 20 accelerated ticks before releasing in tickThrowing. Alternatives: hold for 2 ticks (original) pro: minimal; contra: a single use is rejected if rightClickDelay is above 0 from a prior use. Hold for 6 ticks pro: allows one retry after rightClickDelay expires; contra: still fails under accelerated ticks where client/server drift puts the first two attempts inside a lingering server-side cooldown window. Hold for 20 ticks (chosen) pro: gives 4-5 retry attempts and covers the server-side cooldown expiring mid-hold under accelerated ticks; contra: very slightly wastes ticks when the throw succeeds on the first attempt. Rationale: the server-side cooldown is 20 ticks and the client-side cooldown can clear up to that window before the server one at high -PtickSpeed values, so holding for 20 ticks guarantees at least one attempt hits a cooldown-clear server state. In practice only the first successful attempt throws a pearl, since subsequent presses are silently absorbed by the server fresh cooldown, so the hold does not multiply pearls. See also [[STR-014]].
