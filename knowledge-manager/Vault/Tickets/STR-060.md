# Problem

Neues gui-Modul: Wie kommen Seiten anderer Module in ein gemeinsames In-Game-Menue, ohne dass das GUI-Modul die Features kennt?

# Lösung

Entscheidung: GuiPage-Interface (id, title, createScreen(parent)) plus statische GuiRegistry mit LinkedHashMap - dasselbe Muster wie BehaviorRunner im bot-Modul. Feature-Module registrieren sich in IHRER eigenen Setup-Klasse, nie in der Modul-Hauptklasse (Klassenlader-Regel). Der Abhaengigkeitspfeil zeigt immer vom Feature-Modul auf gui, nie umgekehrt; gui haengt nur am loader. Verworfene Alternativen: (a) eine Widget-Beschreibungssprache statt eines Screen - contra: braucht fuer jedes kuenftige Bedienelement einen neuen Fall, waehrend ein Screen alles kann was Vanilla kann, und alle Seiten sind ohnehin gegen dieselben Vanilla-Widgets geschrieben; (b) eine Config-Screen-Bibliothek wie Cloth Config - contra: der Mod hat bisher keine UI-Fremdabhaengigkeit und jede geplante Seite ist eine Handvoll Buttons und Listen; (c) das gui-Modul kennt die Feature-Module direkt - contra: dreht den Abhaengigkeitspfeil um und macht gui zum Sammelbecken. Kein Auto-Binder von Config-Feldern auf Widgets in v1 - bewusst aufgeschoben, bis es mehr als eine Seite gibt und das Muster sichtbar ist. Drei technische Fallen, die dabei geloest wurden: (1) Ein Client-Command laeuft, WAEHREND der Chat-Screen noch offen ist, und der Chat-Screen schliesst sich danach selbst per setScreen(null) - ein im Command geoeffneter Screen wird also wieder verworfen. Loesung: GuiSetup.requestOpen parkt den Screen und der ohnehin vorhandene END_CLIENT_TICK-Hook oeffnet ihn im naechsten Tick. (2) GuiRootScreen.isPauseScreen() gibt FALSE zurueck - ein pausierender Screen friert im Singleplayer die Welt ein, und das Menue existiert gerade dazu, einen laufenden Bot zu beobachten und zu steuern. Seiten muessen das genauso machen. (3) In 1.21.11 ist die Keybinding-Kategorie kein String mehr, sondern das Record KeyMapping.Category; eigene Kategorien kommen per KeyMapping.Category.register(Identifier). Belegt automatisch RIGHT_SHIFT, das in Vanilla unbelegt ist, und bleibt in den Steuerungen umlegbar. Kein /gui list Unterbefehl: das Wurzelmenue IST die Liste, und ein Literal neben einem freien Wort-Argument macht die Brigadier-Grammatik nur mehrdeutig.
