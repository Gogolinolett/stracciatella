# Problem

Why does the A* search miss better paths when a node is rediscovered with a lower cost, and how is the open set managed?

# Lösung

Decision: use lazy deletion with a closed set instead of open-set tracking. Alternatives: open-set tracker (original) pro: no duplicate records; contra: cannot update the priority of nodes already in the queue, so better paths are missed. Lazy deletion plus closed set (chosen) pro: always uses the best fCost, handles re-discovery correctly; contra: slightly larger priority queue from duplicates. Decrease-key with an indexed priority queue pro: optimal queue size; contra: Java PriorityQueue does not support decrease-key, would require a custom PQ. Rationale: lazy deletion fixes the correctness issue (stale priorities) with minimal code change, and the closed set prevents reprocessing. Standard pattern for A* in Java.
