# Problem

Which scale factor should the Euclidean A* heuristic use in MeshPathfinder, and why does 10.0 produce non-optimal paths?

# Lösung

Decision: scale factor 9.0. Alternatives: scale 10.0 (original) pro: faster search, closer to actual cost; contra: inadmissible for diagonal moves because 10*sqrt(2)=14.14 exceeds the cheapest diagonal cost of 13, so paths are non-optimal. Scale 9.0 (chosen) pro: admissible since 9*sqrt(2)=12.73 < 13, guarantees optimal paths; contra: slightly more nodes explored. Octile distance pro: perfectly tight admissible bound; contra: more complex to implement, gains marginal. Rationale: 9.0 is the largest integer scale that remains admissible given the cheapest diagonal move cost (10 base + 3 diagonal = 13). Simple change with guaranteed optimality.
