# Problem

The bot walks perfectly on the line between nodes and reads as a bot - how is lateral drift added without breaking precise jumps?

# Lösung

Decision: PathWalker injects brief 1-2 tick sideways key presses (left/right) on path segments where the current and next-two nodes are same-Y gap=1, a corridor, with a 40-80 tick cooldown between strafes, disabled on any non-corridor segment. Alternatives: no strafing (state before the change) pro: most predictable movement; contra: every walking step is on the perfect line between nodes, with no lateral drift like a human hand on the keyboard. Continuous low-amplitude strafing on all segments pro: most humanness; contra: single-block-platform jumps need precise alignment, a strafe in flight pushes the player off the landing block and tests fail. Strafe only on safe corridors in brief windows with cooldown (chosen) pro: drifts the bot off-line by about 0.1 blocks on corridors where the alignment-hold and spring camera absorb it, and never touches jump-prep or in-air segments; contra: adds keyLeft/keyRight to the applyMovement surface, and calls during retreat or brake must explicitly pass strafeDir=0. Strafe via random target-offset perturbation pro: no new key state; contra: the existing target offset of 0.05-0.25 blocks already provides micro-variance on the target, whereas strafing varies the input, which is what reads as an imperfect human keyboard hand. Rationale: the isSafeCorridor predicate reliably excludes the failure modes - jumps, sharp turns, retreats - while still firing on the segments where a viewer is most likely to notice the missing drift. applyMovement now explicitly drives all six movement keys so any in-flight strafe is cleared whenever a non-strafing path (jump, brake, retreat) calls it with strafeDir=0.
