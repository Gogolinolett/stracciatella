# Problem

Should pitch use the same spring-damper physics as yaw, or keep the exponential decay?

# Lösung

Decision: both yaw and pitch use spring-damper physics, with pitch using gentler constants (PITCH_ACCEL=0.5, PITCH_FRICTION=0.7) than yaw (TURN_ACCEL=0.8, TURN_FRICTION=0.8). Alternatives: spring-damper on both (chosen) pro: one physics model gives the same feel on both axes, supports the look-speed multiplier and saccades uniformly, and mild overshoot reads as human; contra: pitch can ring slightly more than the old exponential at large deltas. Exponential on both pro: trivially stable, no oscillation; contra: loses the momentum feel, cannot overshoot, cannot carry a saccade, and is asymmetric with yaw. Keep the old asymmetry of spring yaw with exponential pitch pro: it is what existed; contra: a different feel on each axis is visible - a viewer can tell yaw is heavier than pitch - and the multiplier and saccade plumbing would need duplicate code paths. Rationale: a single physics model reduces the look-speed multiplier and saccade implementations to one branch instead of two; the asymmetry was visible on diagonal jumps where pitch tracked instantly while yaw still swept; and PathWalker only consumes the smoothed pitch via setXRot, which is cosmetic, so its jump correctness depends solely on yaw and a different pitch profile cannot break path tests. The gentler pitch constants keep vertical tracking calm so the camera does not feel jumpy on every small terrain step.
