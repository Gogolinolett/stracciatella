# Problem

Wie gibt man dem Bot im Spiel den Teleport-Befehl, mit dem er aus der Grube kommt? Bisher stand exitCommands nur in servers.json und musste von Hand editiert werden.

# Lösung

KURZ: /bot server exit command <command> — greedyString, Slash wird gestrippt, ersetzt statt anzuhaengen. Beispiel: /bot server exit command tp 1 1 1 setzt exitStrategy=COMMAND und schreibt genau einen Befehl. Drei Entscheidungen: (1) greedyString statt string(): tp 1 1 1 sind vier Token; ein Einzelwort-Argument behaelt nur tp, Brigadier scheitert am Rest und der Befehl tut stillschweigend nichts. Falsifiziert: Liste bleibt leer. (2) Fuehrender Slash wird entfernt: der Spieler tippt so wie im Chat, ClientPacketListener.sendCommand will es ohne Slash, sonst fragt der Server nach einem Befehl namens /tp. Falsifiziert: [/t spawn] statt [t spawn]. (3) REPLACE statt APPEND: zweimal tippen heisst nein, den da; ein zweiter Befehl kaeme ohnehin erst an, wenn der erste den Bot schon weggeteleportiert hat. Verworfene Alternative: Unterform add fuer Sequenzen — das Literal add wuerde jeden Serverbefehl beschatten, der selbst mit add anfaengt. Das Feld bleibt eine Liste; echte Sequenzen schreibt man bewusst in servers.json. Warum Befehl und nicht GUI: die SettingsScreen-Zeile kann nur durchklicken, nicht tippen. Ohne Argument schaltet /bot server exit command weiterhin nur die Strategie um und laesst das Konfigurierte stehen; staircase und zurueck verliert den Befehl nicht. Test: Bot exit command reaches servers.json in BotTests, der Reload von der Platte ist die eigentliche Assertion. Siehe [[STR-088]] fuer servers.json selbst.
