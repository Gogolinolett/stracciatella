# Problem

Die Diamond-Miner-Suite (Miner Tests, zwei In-Game-Tests: tunnels at depth, descends and mines diamonds) lief bei jedem Testlauf mit, obwohl der Diamond Miner unbenutzt und in echten Welten kaputt ist. Wie schaltet man sie ab, ohne sie zu verlieren?

# Lösung

Entscheidung 2026-09-10: die Registrierung TestRunner.instance().registerSuite(MinerTests.class) in MinerSetup.init entfernt, mit Kommentar an Ort und Stelle, der Import dazu ebenfalls. Die Klasse MinerTests bleibt samt Deepslate-Sandbox (Bedrock bei -64, Deepslate darueber, Pocket auf Tunnelhoehe, Treppenabstieg), die Suite kommt mit derselben Zeile zurueck. Alternativen: (1) Testklasse loeschen - verworfen, die Sandbox ist Arbeit, die beim Wiederaufgreifen gebraucht wird, und Git-Archaeologie ist teurer als eine ungenutzte Klasse. (2) Ein enabled-Flag an TestSuite oder MinecraftTest im Testing-Framework - verworfen: eine Framework-Erweiterung fuer einen einzigen Fall, und die Registrierung in MinerSetup ist ohnehin der einzige Ort, an dem ein Modul entscheidet, welche Suiten es beitraegt. (3) Die Tests ueber order oder timeout aushebeln - verworfen, das faelscht Ergebnisse. Stand vor der Abschaltung: beide Tests gruen (3,6 s und 8,2 s, die laengsten Einzeltests des Laufs); abgeschaltet werden sie nicht, weil sie scheitern, sondern weil sie Code bewachen, an dem niemand arbeitet, und die Einschaetzung kaputt in echten Welten vom Besitzer stammt. Baseline des vollen Laufs damit 216 statt 218 Tests. Der Suchfilter -Psuites=miner trifft weiterhin die Chunk Miner Tests (Substring auf den Suite-Namen).
