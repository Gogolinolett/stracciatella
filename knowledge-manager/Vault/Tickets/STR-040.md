# Problem

The bot mines with a bare hand and the task fails on timeout when the pickaxe is in inventory storage rather than the hotbar - what is the tool search scope?

# Lösung

Decision: InventoryHelper.selectBestTool scans all 36 main-inventory slots, hotbar plus 27 storage. When the best tool sits in storage (bestSlot 9 or higher) it is swapped into the currently selected hotbar slot via mc.gameMode.handleInventoryMouseClick with ClickType.SWAP before sending the carried-item packet. Alternatives: hotbar only, slots 0-8 (original) pro: minimal, one tight loop; contra: silently fails when the human-style carry tools in a row inventory has the pickaxe in storage, so the bot mines with a bare hand, no ore drops, and the task fails on the maxBreakTicks timeout - which looked like a robustness bug rather than a setup issue. Full inventory plus SWAP packet (chosen) pro: matches what a human player does by noticing the tool in storage, swapping it into the hotbar and mining, and the server-side hotbar held slot ends up with the right tool; contra: one extra container-click packet per tool select that needs swapping, which is small and idempotent, and the SWAP relies on inventoryMenu.containerId which is always valid for the player own inventory so no separate open inventory packet is needed. Move the tool via a direct items.set call pro: no packet; contra: client-only, so the server inventory diverges, the swapped item appears server-side in the original slot, and mining resolves against the wrong tool. Force-give the tool to the hotbar each tick pro: robust in creative; contra: does not work in survival and alters inventory state outside the test expectations. Rationale: full inventory plus SWAP is the cheapest correct answer - one packet the server natively understands, no inventory-state tricks and no creative-only assumptions. Slots 36-40, armor and offhand, are intentionally skipped since they are not tool slots in any practical sense, and the chosen hotbar destination is the currently selected slot so the carried-item packet needs no slot change afterwards.
