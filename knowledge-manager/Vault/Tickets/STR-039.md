# Problem

PathWalker is launched for a 1.5-block two-node path whose first node is the player own position - when should navigation skip the pathfinding pipeline?

# Lösung

Decision: beginNavigation sends targets within reachDistance plus 2.5 blocks straight to POSITIONING, which walks at the target and hands over to LOOKING once in reach, instead of running standoff search plus A* plus PathWalker. Alternatives: always use the full pipeline (original) pro: one code path; contra: debug traces showed PathWalker launched for a 1.5-block two-node path whose first node was the player own position, incurring scan swing, reaction delay, walker start and final settling all for one step, which reads as mechanical orchestration where a player would just take two steps. POSITIONING shortcut for short hops (chosen) pro: the last-couple-blocks walk is literally what POSITIONING is - walk toward the target while looking at it and stop when in reach - so no new mechanics are needed; contra: POSITIONING walks blind without a mesh, which is fine for a couple of blocks on terrain the bot is already standing on, while longer routes keep the full pipeline. Raise reachDistance instead pro: even simpler; contra: changes mining semantics everywhere given server reach limits, and the problem is route ceremony rather than reach. Rationale: POSITIONING already implements the human behavior exactly, and the threshold keeps real navigation - drops, obstacles, distance - on the mesh pipeline.
